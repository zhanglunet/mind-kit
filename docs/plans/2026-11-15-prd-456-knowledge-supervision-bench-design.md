## 1. 问题与目标

第二大脑里进了无法溯源的知识，会越用越错。入库 agent 整理知识时，人工没有一个地方能全程看到一条知识是怎么整理出来的：来源是什么、打了什么标签、中间改过几版。
来源不明的知识要等到进 Wiki 之后才被发现，那时再清理，成本最高。

知识监督台补这一环：每条知识整理时都经过监督台，人可以

- 看到知识的出炉过程（来源、标签、整理版本）；
- 随手批注、裁决；
- 一键把反馈发回 agent，agent 改完再回来。

目标是：来源不明的知识在整理时就被批注发回，个人 Wiki 里只留已经被人点头过的知识。

## 2. 范围与非目标

范围：入库 agent 整理知识全程的人审监督——看、批注、裁决、发回、再回来。

非目标（不属于本监督台，另有 PRD 负责）：

- 不验证知识本身的真假（评审流水线 PRD-433 的事）；
- 不产生新知识（监督台只监督，不整理）；
- 不管知识共建会话（PRD-410 的事）；
- 不做入库知识验证（PRD-387 的事）。

## 3. 数据模型：三件套落账

监督台只存三类记录，全部落账、可追溯：

### 3.1 进度（Progress）

一条知识的一次整理过程是一条进度记录：

- 知识标识：知识编号 + 整理版本号（每次 agent 改完回来，版本号 +1）；
- 整理步骤：来源清单、标签选择、知识初版、修订版（如有）；
- 状态：`整理中 / 待人审 / 已点头 / 已发回 / 已关闭`；
- 时间戳：每步的开始与结束时间。

### 3.2 批注（Annotation）

人对知识的一条意见都是一条批注记录：

- 锚点：批注挂在哪个位置（知识编号、来源条目或标签）；
- 内容：意见正文；
- 类型：`换来源 / 补标签 / 疑问 / 通过`；
- 作者与时间；状态：`待处理 / 已采纳 / 已驳回`。

### 3.3 发回反馈（Feedback）

一次"发回 agent 改"的动作是一条反馈记录：

- 关联的批注列表（一次发回可带多条批注）；
- 发回指令：要求 agent 做什么（换来源 / 补标签 / 只改指定处）；
- 发回时间、agent 回来后的新版本号；
- 闭环：agent 回来后，旧批注逐条标记为"已处理 / 未处理"，未处理的继续挂在新版本上。

三件套之间用整理版本号串联：同一知识的不同版本共享一条进度链，批注与反馈都挂在具体版本上，版本变了，旧批注不丢失。

## 4. 监督接入点与批注方式

### 4.1 接入点

入库 agent 整理知识流程在三个点上向监督台"报到"：

1. **整理开始**：agent 认领一条知识，监督台新建一条进度记录（状态"整理中"）；
2. **整理完成**：agent 交出知识初版，进度记录转为"待人审"，人开始能看到它；
3. **改完回来**：agent 按反馈改完交回新版，进度记录回到"待人审"，版本号 +1，旧批注带到新版上对照。

接入点只做"报到 + 交稿"，不干预 agent 内部的整理逻辑。

### 4.2 批注方式

- 人在知识视图上直接点选一条来源或一个标签，写批注；
- 批注即时保存，不用等整条审完；
- 一条批注可以单独发回，也可以多条批注攒成一次反馈一起发回；
- 发回是一键动作：点"发回 agent"，选中的批注打包成一条反馈记录，agent 侧收到待办。

### 4.3 裁决

人对每条知识只有两种裁决：

- **点头**：知识通过，状态改为"已点头"，进入下游个人 Wiki；
- **发回**：知识不通过，按 4.2 发回 agent 改。

没有"默认通过"：超时未裁决的知识一直停在"待人审"，不自动进入 Wiki。

## 5. "人点头才进 Wiki"的关口

关口规则只有一条，写死在监督台层面：

> 未点头的知识不进个人 Wiki。

- Wiki 入库只读取状态为"已点头"的知识；
- "待人审""已发回""整理中"的知识在 Wiki 里不可见；
- 点头动作本身也是一条落账记录（谁、在什么时候、点了哪条知识、哪个版本）。

## 6. 界面与交互（概念级）

监督台视图分三栏，不规定具体技术实现：

- 左栏：待审知识队列（按"待人审"时间排序）；
- 中栏：当前知识（来源对照知识正文，标签展示，版本切换）；
- 右栏：批注列表与发回面板（写批注、选批注、一键发回）。

交互原则：批注随手写、发回一键走、版本随时切、旧批注不丢。

## 7. 验收标准

1. 设计评审通过（本 T1 的验收标准）。
2. 数据模型能覆盖"进度 + 批注 + 发回反馈"三件套，且同一知识多版本之间批注不丢失（T2/T5 验证）。
3. 三个接入点（整理开始、整理完成、改完回来）都有明确的报到与状态流转定义。
4. 关口可验证：未点头的知识在个人 Wiki 中不可见；超时未裁决不自动放行。
5. 文档与示例中不出现真实内部主机名、IP、账号或密钥，一律用占位符。

## 8. 红线

- 只借鉴形态，代码复用需署名；LoopForge 零代码零文本复用（见第 9 节）。
- 实现类 PR 只开不合并，等用户 review。
- 未点头的知识不进个人 Wiki。
- 本仓既有红线继续生效。
